# Deep outcome interview

Use only when the user picks Deep depth (plan mode recommends it, but the user's answer decides). The aim is the outcome the person would still want if every task in the plan vanished.

## How a round works

1. Ask up to 4 questions with AskUserQuestion. Recommended answer first. Offer real options, not "other".
2. Read the answers. Write the outcome as one sentence.
3. Ask the next round one level down from that sentence.
4. Stop when a stop rule fires.

## The ladder

Each rung asks what the last answer gets them. Climb only as far as the answers keep changing.

| Rung | Ask | A good answer sounds like |
|---|---|---|
| Task | What do you want made or done? | "A monthly report" |
| Use | Who uses it, and for what? | "The board, to decide where to spend" |
| Decision | What decision or action should it drive? | "Cut or keep the two weakest channels" |
| Result | What changes in the business if that goes well? | "Ad spend drops 20% with no lead loss" |
| Number | What number shows it worked, by when? | "Cost per lead under $40 by end of quarter" |

The rewritten spec aims at the highest rung the person confirms, and the check measures that rung where the evidence exists.

## Questions that get under the surface

- If this was done perfectly, what would you stop doing or worrying about?
- What would make you say "that missed the point" even if every box was ticked?
- What has been tried before, and why didn't it land?
- Who else has to be happy with it?
- What's off limits: budget, people, tools, tone, timing?
- What would you cut first if we ran out of time?

## Stop rules

**Case test (only when the outcome is a rule that sorts or routes things: who gets what, which option wins, what goes where).** Before stopping, run the rule on two contrasting real cases it should handle differently. If it gives an odd answer, can't decide, or the user corrects it, ask one more round on that point, within the 5-round cap and unless the user has said go.

Then stop at the first that fires:

- 5 rounds done.
- The next decision is clear.
- The outcome has a number that matters.
- Two rounds in a row added nothing new. Before stopping, check whether the questions were the problem and try one reframed question.
- The person says go.

## Play it back

Before building, show:

- The outcome in one sentence.
- The number and date that show it worked, or "no measure yet" and what would create one.
- The key decisions made in the interview.
- If a case test ran: the two cases and how the rule handles each. If it was skipped because the user said go or the cap hit, say so.
- The assumptions still open.

Ask for an explicit yes. If they change anything, update the sentence, not just the plan.
